## 2. 전체 구조

```
 ┌─────────────── GitHub Actions (매일 새벽 04:07 KST) ────────────────┐
 │  collector/collect.mjs                                              │
 │   └ 심평원 병원정보서비스 API에서 전국 병의원 약 8만 곳 조회          │
 │   └ 개설일자 최근 ~12개월만 남김 (약 1,800곳)                        │
 │   └ site/data/clinics.json 저장 → 저장소에 커밋                      │
 │  → site/ 폴더를 GitHub Pages 로 배포                                 │
 └─────────────────────────────────────────────────────────────────────┘
                              │ (정적 파일)
                              ▼
 ┌─────────────── 사용자 브라우저 ─────────────────────────────────────┐
 │  index.html → clinics.json 다운로드(약 400KB)                       │
 │  위치 권한 → 반경 거리 계산·기간·진료과 필터 → 지도 마커 + 목록       │
 │  지도: 네이버 / 카카오 / OSM 중 설정된 것 (실패 시 OSM 자동 대체)     │
 └─────────────────────────────────────────────────────────────────────┘
```

**핵심 아이디어: 서버가 없다.**
- 데이터는 하루 한 번 미리 모아 **파일 하나**로 만들어 두고,
- 거리 계산·필터는 **사용자 브라우저**에서 합니다.
- 그래서 서버 비용이 0원이고, 응답이 빠르며, API 키가 노출되지 않습니다
  (공공데이터 키는 GitHub Secrets 에만 있고 수집 시에만 사용).

## 3. 파일별 역할

```
new-clinic-map/
├─ .github/workflows/update.yml   매일 수집 + 배포 자동화
├─ collector/
│  ├─ collect.mjs                 심평원 API 수집기 (Node 22, 외부 라이브러리 없음)
│  └─ make-sample.mjs             인증키 없이 화면 확인용 가짜 데이터 생성
├─ site/                          ← 이 폴더가 그대로 웹사이트
│  ├─ index.html                  화면 뼈대
│  ├─ style.css                   디자인 (데스크톱/모바일 반응형, 바텀시트)
│  ├─ config.js                   ★ 지도 회사 선택 + 지도 키 (전환 시 이 파일만 수정)
│  ├─ classify.js                 ★ 진료과 그룹·색상·분류 규칙 (그룹 변경 시 이 파일만 수정)
│  ├─ app.js                      화면 동작 (위치, 필터, 목록, 바텀시트, 통계 이벤트)
│  ├─ map-naver.js                네이버지도 연결 (어댑터)
│  ├─ map-kakao.js                카카오맵 연결 (어댑터)
│  ├─ map-leaflet.js              OpenStreetMap 연결 (키 불필요, 대체용)
│  ├─ favicon.svg                 사이트 아이콘
│  ├─ vendor/leaflet/             Leaflet 라이브러리 (CDN 대신 직접 포함)
│  └─ data/clinics.json           수집 결과 (자동 갱신)
├─ docs/PROJECT_NOTES.md          이 문서
└─ README.md                      설치·운영 안내
```

### 지도 어댑터 인터페이스
세 지도 파일은 모두 **같은 모양의 객체**를 돌려주므로 `app.js`는 어떤 지도인지 모릅니다.

```js
{
  name,                             // "naver" | "kakao" | "leaflet"
  getCenter(),                      // 지도 중심 {lat, lng}
  setRadius(center, radius),        // 반경 원 그리기
  fitRadius(center, radius, padBottom), // 반경이 화면에 맞게 (모바일은 목록 높이만큼 아래 여백)
  setMe(pos),                       // 내 위치 표시
  setMarkers(items, onClick),       // 마커 다시 그리기 (item.color, item.isNew 사용)
  focus(id),                        // 해당 기관으로 이동 + 팝업
}
```
새 지도(예: 구글, VWorld)를 붙이려면 이 7개만 구현한 `map-xxx.js`를 추가하고 `config.js`의 `mapProvider`를 바꾸면 됩니다.

## 4. 데이터: 어디서 받아 어떻게 가공하나

### 출처
- **건강보험심사평가원 병원정보서비스** (공공데이터포털, 무료)
- 엔드포인트: `https://apis.data.go.kr/B551182/hospInfoServicev2/getHospBasisList`
- 인증: 공공데이터포털 **일반 인증키(Decoding)** → GitHub Secret `HIRA_SERVICE_KEY`

### 사용한 요청 파라미터
| 파라미터 | 값 | 비고 |
|---|---|---|
| `clCd` | 종별코드 | 종별마다 따로 조회 (한의원 등 제외 목적) |
| `numOfRows` | 1000 | 1000건/페이지 허용됨을 실제로 확인 |
| `pageNo` | 1.. | |
| `_type` | json | 인증 오류 시엔 XML 로 응답하므로 별도 처리 |

### 조회하는 종별코드 (`CLASS_CODES`)
`01` 상급종합병원, `11` 종합병원, `21` 병원, `28` 요양병원, `29` 정신병원, `31` 의원, `41` 치과병원, `51` 치과의원, `61` 조산원, `71` 보건소, `72` 보건지소, `73` 보건진료소, `75` 보건의료원
→ 제외: `92` 한방병원, `93` 한의원

### 사용한 응답 필드
| 필드 | 의미 | 저장 키 |
|---|---|---|
| `ykiho` | 기관 고유 ID | `id` |
| `yadmNm` | 기관명 | `n` |
| `clCdNm` | 종별명 (의원/병원…) | `t` |
| `addr` | 주소 | `a` |
| `telno` | 전화 | `p` |
| `hospUrl` | 홈페이지 | `w` |
| `estbDd` | **개설일자** (YYYYMMDD) | `d` |
| `YPos` / `XPos` | 위도 / 경도 (WGS84) | `y` / `x` |

- 저장 시 **개설일자 최근 380일**만 남김 (화면은 12개월, 며칠 여유).
- 결과: 전국 약 8만 곳 조회 → 약 1,800곳 저장, 파일 약 400KB.
- 파일 형식: `{ updatedAt, source, count, partial?, items: [...] }` (`partial` = 이번에 못 받고 이전 데이터를 유지한 종별)

### 진료과 분류 방법 (`classify.js`)
기본 API에는 **진료과 정보가 없습니다.** 그래서 **기관 이름 속 진료과(표방과목)**로 분류합니다.
(의료법상 전문의만 기관명에 전문과목을 표시할 수 있어 이름이 꽤 믿을 만한 단서)

1. 종별이 치과의원/치과병원 → 치과
2. 이름에서 진료과 단어를 **긴 것부터** 찾고 찾은 부분은 가림
   - 예: "정형외과"를 먼저 찾아 가려야 "외과"로 잘못 잡히지 않음
3. 여러 개가 나오면 1~4그룹에 해당하는 것 우선, 그중 이름 앞쪽 것
   - 예: "행복내과소아청소년과의원" → 내과
4. 진료과가 없는 **의원**은 보조 단서로 추정
   - `피부|뷰티|모발|에스테틱` → 피부·미용(추정)
   - `튼튼|관절|척추|통증|마디` → 정형·통증(추정)
   - `여성` → 여성의원
   - 그 외 → **일반의원**
5. 진료과가 없는 병원급·보건소 → 기타

실제 데이터 분석 결과(전국 12개월): 일반·내과계 714 / 정형·통증·신경 363 / 치과 453 / 피부·성형·안과 등 278 / 기타 45.
의원 중 약 40%는 이름에 진료과가 없음 → 정확도 한계(11장 참고).

## 9. 테스트 방식

외부 서비스(공공 API, 카카오, 네이버, 통계)가 개발 환경에서 막혀 있어도 검증할 수 있도록 **대역(가짜)**을 적극 사용했습니다.

| 대상 | 방법 |
|---|---|
| 화면 전체 | `make-sample.mjs` 가짜 데이터 → 로컬 서버 → Playwright(헤드리스 크롬)로 PC·아이폰 크기 스크린샷 |
| 위치 권한 | Playwright 에서 위치 허용(수원/서울 좌표) / 거부 두 경우 |
| 지도 SDK | 카카오·네이버의 API 모양만 흉내 낸 **스텁** 스크립트로 바꿔치기 → 마커 수, 팝업 열기/닫기, 목록 연동, 호출된 메서드 확인 |
| 인증 실패 | 스텁에서 인증 실패 신호 발생 → OSM 대체 확인 |
| 네이버 높이 버그 | 스텁이 실제처럼 `position: relative` 강제 → 수정 전후 지도 상자 크기 비교 |
| 수집기 실패 대응 | **가짜 심평원 API 서버**: 특정 페이지는 처음 N번 실패, 특정 종별은 항상 실패 → 이어받기·이전 데이터 유지 확인 |
| 분류 규칙 | 예시 이름 목록 + 실제 1,853건 전체 분류 통계 |
| 통계 이벤트 | `goatcounter.count` 를 가로채 버튼별 이벤트 이름 확인 |
| 배포 | GitHub API 로 Actions 실행 상태를 주기적으로 조회 |

**한계:** 실제 카카오/네이버 지도 위 모습, 아이폰 사파리(WebKit) 동작은 개발 환경에서 재현 불가 → 사용자가 실제 기기에서 확인하고 캡처로 피드백.

## 11. 한계와 남은 과제

### 알려진 한계
- **개원일 = 심평원 개설일자.** 이전 개원(이사)도 신규로 보일 수 있고, 실제 개원과 데이터 반영 사이 수 주 시차 가능.
- **진료과 정확도:** 이름에 진료과가 없는 의원(약 40%)은 "일반의원"으로 분류 → 실제로는 피부·미용, 통증 클리닉인 곳이 섞임.
- **부분 실패 시** 이전 데이터를 쓰므로, 그 사이 폐업한 곳이 하루 이틀 더 보일 수 있음.
- 심평원 API가 혼잡하면 수집이 오래 걸리거나 일부 실패.
- 공개 저장소의 예약 실행은 저장소 활동이 오래 없으면 GitHub 가 중지할 수 있음(매일 데이터 커밋이 있어 보통 유지).

### 남은 과제 (우선순위 제안)
1. **아이폰 사파리 표시 확인** (진행 중)
2. 제작자 표시 + ⓘ 서비스 소개 창 ("위치는 저장하지 않음" 안내 포함)
3. 카카오톡 공유 미리보기(OG 태그, 대표 이미지)
4. 포트폴리오용 README (스크린샷, 해결한 문제, 기술)
5. 갱신 시각까지 표시 (`2026.11.27 04:52`)
6. 진료과 정확도 개선: **의료기관별상세정보서비스** 추가 신청 → 신규 기관만 진료과목 조회해 캐시
7. 도메인 구입·연결 (정식 서비스 시) — 카카오·네이버에 새 도메인 추가 등록 필요
8. 앱 전환 (웹을 감싸는 방식 또는 `clinics.json` 재사용)

## 12. 다른 프로젝트에 재사용할 패턴·교훈

### 구조 패턴
1. **"매일 모아 파일 하나" 패턴** — 데이터가 자주 안 바뀌고 크지 않다면 서버·DB 없이
   `예약 실행(Actions) → JSON 생성 → 정적 호스팅(Pages)`으로 충분. 비용 0원.
2. **외부 서비스는 어댑터로 분리** — 지도·결제·알림 등 바뀔 수 있는 것은 같은 인터페이스로 감싸고 설정 파일로 선택.
3. **실패 시 대체(Fallback)** — 키 오류·외부 장애에도 화면이 깨지지 않게 기본 대안을 준비.
4. **설정·규칙은 한 파일에** — `config.js`(키·제공자), `classify.js`(분류 규칙·색상). 비개발자도 고칠 위치가 명확.
5. **샘플 데이터 모드** — 키 발급 전에도 화면을 완성·검증.

### 공공데이터 API 다룰 때
- 서버 혼잡(오류 99)·타임아웃은 **일상**이다 → 재시도 + 지수 대기 + **이어받기** + **부분 실패 허용**.
- 받은 양이 비정상이면 **기존 데이터를 덮어쓰지 않는다.**
- 페이지 크기(1000)·트래픽 한도는 실제로 호출해 확인.
- 인증 오류는 JSON 이 아니라 XML 로 오는 경우가 있으니 파싱 실패를 따로 안내.

### 지도 SDK 다룰 때
- 키는 공개되지만 **도메인 등록**으로 보호된다. 형식: `https://도메인` (경로·끝 `/` 없이).
- SDK가 **컨테이너 스타일을 바꿀 수 있다** → 전용 안쪽 상자를 만들어 넘기기.
- 인증 실패가 **비동기로 늦게** 올 수 있다 → 실제 렌더링(타일 로드) 확인 후 성공 처리.
- 콘솔에 오류가 없는데 안 보이면 → 크기(높이 0)·겹침(z-index)부터 의심.

### 배포·운영
- 정적 사이트는 처음부터 **캐시 무효화(버전 꼬리표)**.
- 자동 커밋하는 저장소에 사람이 push 할 땐 **실행 중인 작업이 끝난 뒤**에.
- 예약 실행은 **사용자 계정으로** 워크플로를 한 번 수정해 등록하면 안정적.

### 협업(사람 + AI)
- 사람은 **기준을 결정**(신규 기간, 진료과 그룹, 화면 우선순위), AI는 **실데이터로 근거를 제시**(빠진 진료과 목록·개수)하고 구현.
- 화면 문제는 **캡처**, 오류는 **콘솔(F12) 캡처**가 가장 빠른 소통 수단.
- 비밀값(공공데이터 키, Client Secret)은 채팅에 붙이지 않고 해당 서비스 설정 화면에 직접 등록.

## 13. 작업 방식: 사람과 AI의 역할 분담

| 역할 | 사람(기획자) | AI 코딩 도구 |
|---|---|---|
| 기획 | 서비스 아이디어, 대상(웹→앱), 신규 기준(3/12개월), 제외 대상 | 가능한 방식·장단점 설명, 추천안 제시 |
| 기준 결정 | 진료과 그룹 구성, 기간 필터, 모바일 배치, 지도 회사 | 실데이터 분석으로 빠진 항목·개수 보고, 결정 필요한 지점 질문 |
| 외부 계정 | 공공데이터·카카오·네이버·GitHub·GoatCounter 가입과 키 발급, 권한 부여 | 단계별 설정 방법 안내, 흔한 실수 경고 |
| 구현 | — | 코드 작성, 자동화, 테스트(스텁·가짜 서버), 배포, 상태 감시 |
| 검증 | 실제 기기·실제 지도에서 확인, 캡처 피드백 | 원인 분석, 수정, 재배포 |

**작업 흐름 한 사이클**
`요청 → (필요시) 방식 설명·추천 → 결정 → 구현 → 자동 테스트·스크린샷 → 배포 → 사용자 실기기 확인 → 캡처 피드백 → 수정`
